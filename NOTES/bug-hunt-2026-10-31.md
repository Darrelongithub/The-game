# Bug hunt — live party game (4–11 phones, nobody can refresh)

Date: 2026-10-31 · Branch: `arena/12723274-the-game` · Base commit: `483121a`

Scope discipline: only **STALL** (a phone can't answer / a round never closes / a reveal
never lands / a crash mid-night), **LEAK** (a private answer on the wrong screen, a sign-up
attribute in a payload, a narrowed pick list that reveals intent) and **LIE** (a reveal that
states something the log does not support: a mis-tallied metric, a verdict with no answers, a
dropped prompt shrinking a tally, a name bound to the wrong half of a pair). Naming, structure,
taste and refactors are out of scope and are not listed here.

Every confirmed bug below ships with a test that fails on its parent commit (the line it dies on is
quoted) or an exact command + wrong output. One commit per finding, each with its regression test,
plus the owner's product change (no age/terms gate) and its test updates.

---

## 1. Confirmed bugs (severity order)

### B1 — night-ruining · LEAK/STALL · a profile-less join erased the whole room on the next restart
`apps/server/src/game.ts:451` (join gate, pre-fix) · commit **`487df4f`** · test `apps/server/test/join-profile.test.ts`

`join` accepted a seat without a profile through a dead `(input as {demo?}).demo !== true`
escape. `JoinRequest` has no `demo` field (it is a `create`-only flag), so a client that sent
`profile: undefined` was let in, stored as `profile: undefined`, and `restore()` — which
re-validates every player before rehydrating a room — then threw the **entire room** away on the
next boot: every phone came back to "Room not found." with the night's log orphaned on disk.

Repro (pre-fix): `.scratch/probe-profilejoin.ts` → `join` without a profile returned `ok: true`;
after a server restart the same room's `join`/`resume` returned `Room not found.`
Guest-visible effect: the whole party loses the night — nobody can rejoin, the log is stranded.
Fails on `483121a` at `apps/server/test/join-profile.test.ts` line 61 ("a real room demands the
profile on join": `assert.equal(ack.ok, false)`; old code returns `true`).
Fix: the join gate demands a valid profile for every non-resume join (the `create` escape stays,
because `create` writes `neutralProfile`, which *does* pass `validProfile`).

### B2 — party-ruining · LIE · a gamertag shaped like a pseudonym re-named another guest in public copy
`apps/server/src/pseudonyms.ts:11` (`pseudonymizeText`) · commit **`ea70c81`** · test `apps/server/test/pseudonyms.test.ts`

Aliases were substituted one at a time, so a later alias could match a token an earlier alias had
just written. `"Player 3"` is a legal 2–14 char alias (no reserved-name check), so a guest who
picked it hijacked the token of the guest at seat 3: every mention of *Samantha* pseudonymized to
`Player 4` and restored to **"Player 3"** — a different person — in finale quotes and dodge
slides shown to the whole room.

Fails on `483121a` at `apps/server/test/pseudonyms.test.ts:26`:
`expected: 'Player 3 waved at Player 4.'` / `actual: 'Player 4 waved at Player 4.'`
Live proof (`npx tsx .scratch/probe-player-token.ts` → `caseA_tokenShapedAlias`, 4 seats Ada/Ben/Samantha/`Player 3`, zero API keys):
old code's public finale body → `"Player 3 should do this instead of me." — Ada` (Samantha was the
one named); after the fix → `"Samantha should do this instead of me." — Ada`.
A cross-roster sweep (`apps/server/src/pseudonyms.ts` directly, 4–5 name rosters from 34 plausible
aliases) found 37,664 mis-bound alias mentions before the fix.

Guest-visible effect: the finale puts a named statement against the wrong guest, in public, with
no way to undo it.
Fix: one pass over one alternation, so an emitted token can never be rescanned
(`pseudonymizeText` now builds a single case-insensitive whole-token regex and maps each match to
its token). All 104 prompts / 81 narrator / 72 server tests stay green; `smoke:oracle`,
`smoke:verified` and `smoke:demo` all pass.

### B3 — party-ruining · STALL · a hand-answered demo seat was refused on every rating/ios beat
`apps/server/src/game.ts:154` (`assignDemoValue`) + `:667` (`demo_answer_as`) · commit **`60852ae`** · test `apps/server/test/demo-answers.test.ts`

`demo_answer_as` forwarded the host's value verbatim, but rating rounds assign one subject **per
seat** plus one trait for the whole round, and ios rounds assign one subject per seat. `submit`
rejects anything else (`"Answer must use your assigned subject."`), so every hand-answered puppet
was refused and the beat had to wait out its timer — the host cannot puppet a rating/ios beat at
all.

Repro (pre-fix): `.scratch/probe-demo-rating.ts` (1 host + 3 puppets) → seat C and D both
`["Answer must use your assigned subject."]`; after the fix all three `ACCEPTED`, host `{ok:true}`.
Fails on `483121a` at `apps/server/test/demo-answers.test.ts` test 2 ("every puppet seat can
hand-answer a rating round" — re-verified: removing the single `assignDemoValue(...)` call in the
handler turns it into `not ok 2 … "no seat's answer is refused"`).
Fix: `assignDemoValue()` derives the seat's own subject (and the round trait) on the server, where
the assignment lives; the client is never told a puppet's assignment (a client-side attempt was
written and reverted — the phone cannot know it).

### B4 — party-ruining · LIE · a guest's typed "Player 2" came back out as a real guest's name
`apps/server/src/pseudonyms.ts` (`restoreAliases`) · commit **`70c434c`** · test `apps/server/test/player-token.test.ts`

`restoreAliases` maps every whole `Player N` token to the alias of seat N, and player text is
pseudonymised on the way to services — so a sentence that already contained a token survived
storage and was rewritten on the way out. A performer's pass reason `"Truth is, Player 2 should do
this instead of me."` was published to the room as `"Truth is, Ben should do this instead of me."`
Guest-visible effect: the finale puts a named statement against a guest the sentence never named.
Fails on its parent commit (`562fa3f`) at `apps/server/test/player-token.test.ts:118`:
`expected: 'Truth is, Player 2 should do this instead of me.'` / `actual: 'Truth is, Ben should do this instead of me.'`
Fix: a typed token leaves the token grammar when the answer is stored (one invisible ZWSP), and
public copy strips the marker, so what a guest reads is exactly what they typed. Aliases stay
unrestricted (owner decision) — a guest may still call themselves "Player 3".

### B5 — party-ruining · LIE · a tied verdict was announced as "The room decided"
`apps/server/src/game.ts:1121-1131` (`buildReveal`, verdict branch) · commit **`e72f8f4`** · test `apps/server/test/verdict-tie.test.ts`

The tally was sorted and `ranked[0]` published as the room's verdict even when the top count was
shared, so a 2–2 split was stated as a decision the votes do not support (the numbers underneath
were right; the *claim* was not).
Fails on its parent commit (`562fa3f`) at `apps/server/test/verdict-tie.test.ts:116`:
`a 2–2 tie is not a decision (got "The room decided: Ada")`.
Fix: a tie names both sides — `The room split: Ada / Ben`, slide body `2 of 4 each — the room
split.` — and the honest numbers ride along. The offline mock mirrors the rule.
One existing assertion was widened (`apps/server/test/live-moments.test.ts:260`): it pinned the
body to `/^\d+ of \d+ said it out loud\.$/` while its own night produces a four-way 1–1–1–1 split,
i.e. it was asserting the defect. It now accepts either wording; `verdict-tie` proves the split
independently against the old code.

## 2. Owner decisions and open rulings

### Applied: the door has no age/terms gate (commit `85dcdff`)
The owner knows their guest list, so the 18+ attestation and the house-rules checkbox are gone:
`Consent` keeps only `revealOptIn` (the private-card opt-in the game actually uses, normalised
server-side, absent = opted out), `create`/`join` accept alias + profile only, both checkboxes are
removed from `JoinScreen`, and `mockTransport` mirrors it. Spec §1/§3 and RUNBOOK updated.
Tests edited on purpose (owner override of "never edit a test", each an assertion of the removed
gate): `apps/server/test/protocol.test.ts:45`, `apps/web/src/components/__tests__/regressions.tsx:60`,
`apps/web/scripts/mock-flow.test.ts:160`, `apps/web/scripts/ssr-smoke.test.ts:56`,
`apps/web/scripts/live-socket-smoke.mjs:36`.
**Still enforced:** the profile questionnaire keeps its 18–120 age range (`validProfile`), because
that answer is game data rather than a door. Say the word and the floor drops too.

### R2 — token-shaped aliases stay legal (decided: no change)
A guest may name themselves "Player 3", so their name and seat 3's pseudonym are the same string.
The owner chose names over namespace hygiene, so nothing is rejected at the door; B2 and B4 are
what make that safe (no hijack, no rebinding). Residual effect, cosmetic: on a provider-polished
slide a token and a nickname are visually indistinguishable.

### R4 — live rooms are memory-only across a server restart (still open)
`apps/server/src/game.ts:283-300` (`restore()`), `persistRoom`

Rooms, rounds, reveals and timers live in `this.rooms`; only the roster and the log are persisted,
and `restore()` deliberately drops rooms it cannot fully revalidate (B1 was one such path). A host
restart still ends the night for everyone, and no spec line promises otherwise. This is a feature
decision, not a one-line fix: it needs persisted round/reveal state and timer re-arm, so it stays a
ruling.

## 3. Gaps (real coverage holes; no live defect proven)

- **~~Consent guard weakening is untested~~** — moot since `85dcdff`: there is no age/terms check
  to weaken. What remains tested is the profile gate (`validProfile`), which still requires 18–120.
- **Word-boundary asymmetry.** `redactAliases`/`containsAlias` (`packages/prompts/src/provider.ts:100,119`)
  use `(?<![\p{L}\p{N}])` while `pseudonymizeText` uses `(?<![\p{L}\p{N}_])`, so `ada_1` is a
  boundary-safe alias in one and not the other. No reachable leak found: pseudonymization runs
  before redaction on every provider payload, so the weaker net is never the only net.
- **`pseudonymizeText` is not idempotent whenever an alias looks like a token** (R2). Production
  pseudonymizes once per boundary today (`redactValue` on a log copy; nothing re-pseudonymizes an
  already-pseudonymized string), so it does not bite — but nothing asserts that invariant either.
- **`.env.example` never mentions `SPICY_TIER`,** although `packages/prompts/src/bank/index.ts:78`
  reads it and `README.md`/`packages/prompts/README.md` document it. Documentation gap only; the
  one place a host would look for it is the file that is missing it.
- **No test pins the display's round mirror for the spotlight cover.** The idle-cover behaviour is
  correct (probed), but only an ad-hoc probe asserts it.
